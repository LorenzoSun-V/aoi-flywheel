# 清单格式 1

一个数据集版本的内容就是一份清单：这个版本里**每一个**文件的路径、SHA-256 和大小。清单从来不是相对父版本的增量，读任何版本都不需要它的父版本。

代码在 `client/fw/contract.py`，客户端和服务端共用这一份；数据库里冻结版本时用 SQL 按同样的规则重算（`server/fwserver/migrations/0001_init.sql` 里的 `version_manifest_sha256`），两边的结果由测试保证一致。

## 格式

```
fw-manifest 1
line01/img0000001.bmp	9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08	786486
line01/img0000001.json	60303ae22b998861bce3b28f33eec1be758a213c86c93c076dbe9f558c11c752	1043
```

- UTF-8，换行只用 LF，最后一行后面也有一个 LF。
- 第一行固定是 `fw-manifest 1`。
- 之后每个文件一行：`路径<TAB>sha256<TAB>大小`。sha256 是 64 位小写十六进制；大小是字节数，十进制，不带前导零。
- 按路径的 UTF-8 字节排序，路径不重复。
- 清单本身也作为一个文件存进文件库，它的 SHA-256 就是这个版本内容的标识：两个版本的清单哈希相同，内容就完全相同。

读清单时任何一处不符合上面的写法都算错，不做“宽容解析”，所以同样的内容只有一种写法、只有一个哈希。

## 路径

路径相对数据集根目录，用 `/` 分隔，必须在 Windows 和 Linux 上都能原样放到磁盘上：

- 不能为空，不能以 `/` 开头，不能有空的一级、`.` 或 `..`；
- 必须是 Unicode NFC 写法，整条路径不超过 1024 字节；
- 不能含控制字符和 `< > : " | ? * \`；
- 每一级不能以空格或点结尾，不能是 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，带不带扩展名都算）；
- 同一个版本里不能有只差大小写的两个路径（在 Windows 上会撞），一个名字不能既是文件又是目录。

导入时 `fw` 先按这些规则检查整个目录，有问题就列出来、不导入。

## 差异

两个版本的差异直接比两份完整清单：

- 新增、删除：路径只在一边；
- 修改：路径相同、哈希不同；
- 改名：删除的路径和新增的路径内容相同（哈希相同）。按路径顺序一对一配对，所以一个文件复制到两个新位置、原位置删掉，算一次改名加一次新增。

导入前的预览（客户端）和平台上的差异（服务端）用同一个函数 `classify_changes`，两边的数字总是一样的。

## 导出目录

`fw export` 给连不上平台的机器用：

```
SES-TX@3/
  data/              版本里的全部文件
  fw-manifest.txt    这个版本的清单（上面的格式）
  fw-version.json    版本信息：ref、id、数据集、版本号、清单哈希、文件数、总大小、建立时间和人、导出时间
```

`fw verify <目录>` 不需要平台：检查 `fw-manifest.txt` 的哈希和 `fw-version.json` 里记的一致，`data/` 里不多不少正好是清单里的文件，每个文件的大小和 SHA-256 都对。
